# CLI command implementations

This directory holds one file per command (or per closely-related
group). The dispatcher and option structs live one level up; see
[../README.md](../README.md) for the higher-level layout and build
pipeline.

For the user-facing command list, see the top-level
[README.md](../../../../README.md#cli-commands).

## Files

### Command implementations

| File | Commands |
|---|---|
| `init.cpp` | `cppup init` |
| `build.cpp` | `cppup build` (drives the full pipeline; also calls auto-sync) |
| `test.cpp` | `cppup test` |
| `clean.cpp` | `cppup clean` |
| `compile_commands_cmd.cpp` | `cppup compile-commands` |
| `format.cpp` | `cppup format` |
| `tidy.cpp` | `cppup tidy` |
| `package.cpp` | `cppup package add / list / remove / lock / sync`, and the top-level `lock`/`sync` aliases |
| `toolchain.cpp` | `cppup toolchain add / list / remove / select`, and `cppup profile select` (shares the lockfile selection machinery) |
| `registry.cpp` | `cppup registry set` |
| `module.cpp` | `cppup module add` |
| `plugin.cpp` | `cppup plugin add / list / remove` (`add` is a scaffolding stub — see [docs/plugin_api.md §6](../../../../docs/plugin_api.md)) |
| `update.cpp` | `cppup update` (and is the only command compiled into the slim bootstrap binary) |

### Shared infrastructure

| File | Purpose |
|---|---|
| `common.h` | File discovery (`find_files`), shell helpers (`command_exists`, `execute_command`), archive extraction, environment probes used across commands. |
| `lockfile.{hpp,cpp}` | `cppup.lock` parser, writer, and the deterministic serializer used by `lock` / `sync` / `*-select`. |
| `selection_resolver.{hpp,cpp}` | Resolves the active toolchain + profile (CLI flag > lockfile > env > default) and exports `CPPUP_ACTIVE_*` env vars before `build.cpp` is compiled. |
| `source_selection.{hpp,cpp}` | Parses the `--git / --dir / --url / --tar / --zip / --version` family of flags into a normalized `PackageInfo`. |
| `install_paths.{hpp,cpp}` | `--user` install root: prefers `$XDG_DATA_HOME/cppup/`, falls back to `$HOME/.cppup/`. |
| `coverage_parser.{hpp,cpp}` | Parses gcov output for `cppup test --coverage`. |
| `init_templates_data.hpp` | Generated by `scripts/embed_init_templates.sh` — bakes `templates/init/**` into the binary. |
| `embedded_configuration_header.hpp` | Embedded copy of `<cppup/configuration.hpp>` for `init` and the configure-compile step. |

### Tests

## Conventions

- Every command returns `std::expected<int, std::string>`. `int` is the
  intended process exit code (0 on success).
- User-input boundaries (CLI argument parsing, file IO, manifest
  parsing) use `std::expected`. Internal invariants use `CPPUP_CHECK`
  and panic on violation.
- Commands accept a `CommandContext&` (logger, project root, env) so
  they can be tested without going through `cli_application.cpp`.
- New commands register through `CliApplication::register*Commands` in
  [../cli_application.cpp](../cli_application.cpp).
